# Quran Tafseer Transcription

A reusable Manus skill and companion script set for transcribing multilingual Quran tafsir lectures, especially recordings that combine Hausa commentary with Arabic Quran recitation or quotations.

The workflow is designed to:

- Preserve the original audio and raw automatic transcription.
- Improve difficult speech recordings conservatively before re-transcription.
- Split long recordings into service-safe, timestamp-aligned chunks.
- Keep Hausa commentary in Hausa and rewrite Arabic-script Hausa into Latin Hausa when needed.
- Preserve identifiable Quranic passages in Arabic script with references.
- Distinguish recitation, Arabic quotations, Hausa explanation, and uncertain speech.
- Produce structured JSON suitable for a synchronized transcript application.
- Flag uncertain wording instead of silently inventing a confident reading.

## Repository contents

```text
SKILL.md
scripts/
├── enhance_audio.py
├── transcribe_aligned_chunks.py
└── validate_transcript.py
```

`SKILL.md` contains the instructions Manus follows when this skill is triggered. The scripts provide deterministic helpers for the audio-processing and quality-control portions of the workflow.

## Installation in Manus

This repository is intended to be used as a Manus skill. To install it:

1. Open the public repository:
   [humanshado/quran-tafseer-transcription](https://github.com/humanshado/quran-tafseer-transcription)
2. Add the skill to **My Skills** using the repository's `SKILL.md`.
3. In a new task, refer to the skill or ask Manus to transcribe a Hausa-Arabic Quran tafsir recording.

For local development or testing, clone the repository:

```bash
git clone git@github.com:humanshado/quran-tafseer-transcription.git
cd quran-tafseer-transcription
```

The scripts use Python's standard library and do not require a Python package installation.

## System requirements

The workflow assumes a Manus environment with the following command-line utilities:

- Python 3.10 or newer
- FFmpeg and FFprobe
- `manus-speech-to-text`
- `manus-node` when using the optional built-in LLM normalization step

Check the basic tools with:

```bash
python3 --version
ffmpeg -version
ffprobe -version
manus-speech-to-text --help
manus-node --help
```

The speech-to-text command and built-in LLM runtime are provided by Manus. They are not installed through this repository.

## Recommended end-to-end workflow

### 1. Inspect the source audio

Always keep the source file unchanged. First inspect its duration, codec, sample rate, channels, and bitrate:

```bash
ffprobe -v error \
  -show_entries format=filename,duration,size:stream=codec_name,sample_rate,channels,channel_layout,bit_rate \
  -of default=noprint_wrappers=1 \
  /path/to/lecture.mp3
```

For long or noisy recordings, also inspect loudness:

```bash
ffmpeg -hide_banner -i /path/to/lecture.mp3 \
  -af volumedetect -f null - 2>&1 | tail -20
```

### 2. Create enhanced derivatives

Use the enhancement helper to create a speech-oriented WAV and MP3 while retaining the original:

```bash
python3 scripts/enhance_audio.py \
  /path/to/lecture.mp3 \
  /path/to/working/audio
```

The default processing chain applies:

- A mild high-pass filter at 70 Hz to reduce rumble.
- A low-pass filter at 5 kHz appropriate for low-sample-rate speech.
- Moderate FFmpeg noise reduction.
- Loudness normalization.
- Mono conversion and 16 kHz resampling.

The output files are named `<original>_enhanced.wav` and `<original>_enhanced.mp3`. Enhancement improves consistency and intelligibility but cannot recreate information that was never captured by the original recording.

### 3. Probe transcription availability

Before submitting a full lecture, test a short sample:

```bash
mkdir -p working/probe
ffmpeg -y -hide_banner -loglevel error \
  -ss 0 -t 60 -i working/audio/lecture_enhanced.mp3 \
  -c:a copy working/probe/opening_60s.mp3

manus-speech-to-text working/probe/opening_60s.mp3 \
  --granularity segment \
  --terminal-max-len-single 5000
```

If the service reports `402 Payment Required` or insufficient credits, stop the batch and wait for credits. Do not repeatedly retry a fatal credit error.

### 4. Transcribe aligned chunks

Use the enhanced MP3 rather than a large PCM WAV. Five-minute chunks generally remain within upload limits while preserving usable timing:

```bash
python3 scripts/transcribe_aligned_chunks.py \
  working/audio/lecture_enhanced.mp3 \
  working/transcription
```

To choose another chunk size:

```bash
python3 scripts/transcribe_aligned_chunks.py \
  working/audio/lecture_enhanced.mp3 \
  working/transcription \
  --chunk-seconds 240
```

Each chunk produces:

- An MP3 file with reset local timestamps.
- A raw `.txt` transcription containing timestamped segments.
- JSON output generated by `manus-speech-to-text` in the same directory.

Add the chunk offset to every local timestamp when merging. Never delete a chunk merely because its output is empty.

### 5. Recover an empty chunk

An empty transcription can be caused by a service or chunk-boundary issue even when the audio contains speech. Check the audio first:

```bash
ffprobe -v error -show_entries format=duration,size \
  -of default=noprint_wrappers=1 working/transcription/chunk_09.mp3

ffmpeg -hide_banner -i working/transcription/chunk_09.mp3 \
  -af volumedetect -f null - 2>&1 | tail -10
```

If it is non-silent, split only that chunk into shorter parts, typically 60 seconds, and transcribe the parts. Add the subchunk offset to the parent chunk offset during the merge. Do not redo successful chunks unless necessary.

## Hausa Latin-script normalization

Automatic speech-to-text may select Arabic as the language for a mixed Hausa-Arabic lecture. It may therefore render Hausa commentary with Arabic characters or classify it as unmatched recitation.

Do not fix this with a mechanical character-by-character substitution. Hausa spoken in Arabic script is often phonetically distorted by the recognizer, so normalization requires context and audio review.

For each affected segment, retain a structure such as:

```json
{
  "id": "enh-0324",
  "start": 1500.1,
  "end": 1504.6,
  "rawText": "Arabic-script automatic output",
  "text": "Latin Hausa editorial transcription",
  "type": "hausa_commentary",
  "arabicText": "",
  "confidence": "low",
  "note": "Some words remain unclear and require audio review.",
  "sourceChunk": 5
}
```

Normalization rules:

1. Preserve `rawText` exactly for auditability.
2. Write corrected Hausa in standard Latin Hausa orthography.
3. Use Hausa letters such as `ƙ`, `ɗ`, and `ɓ` only when supported by the audio and context.
4. Preserve Arabic Quran quotations in Arabic script rather than transliterating them.
5. Mark uncertain words with a low confidence value and a note.
6. Classify the result as Hausa commentary, not unmatched recitation, when the audio is explanatory Hausa speech.
7. Do not translate the Hausa into English unless explicitly requested.

## Quranic Arabic handling

Identify Quranic quotations separately from the Hausa explanation. For every confidently identified verse, record:

- Surah name and number.
- Ayah number.
- Verified Arabic text.
- Audio timestamp or segment reference.
- Whether the speaker is the reciter or lecturer.

Verify Quran text using an authoritative source such as Quran.com or Tanzil. If a quotation is uncertain, retain the raw transcription and mark it for review rather than fabricating an Arabic correction.

## Suggested JSON schema

A synchronized application can consume segments with this minimum shape:

```json
{
  "schemaVersion": "1.0.0",
  "sourceAudio": "lecture_enhanced.wav",
  "duration": 3814.87,
  "segments": [
    {
      "id": "enh-0001",
      "start": 1.9,
      "end": 17.3,
      "rawText": "Original ASR output",
      "text": "Displayed Latin Hausa or Arabic text",
      "type": "commentary",
      "arabicText": "",
      "confidence": "medium",
      "note": "Review note",
      "sourceChunk": 0
    }
  ]
}
```

Recommended `type` values:

- `commentary`
- `hausa_commentary`
- `quran_arabic`
- `recitation`
- `hadith_or_arabic_quote`
- `mixed`
- `uncertain`

## Validation

Validate a merged JSON transcript with:

```bash
python3 scripts/validate_transcript.py \
  working/transcription/lecture_latin_hausa.json
```

The validator checks that:

- Segments exist and have non-empty display text.
- Segments are chronological.
- Segments do not overlap.
- Low-confidence segments remain countable.
- Arabic quotation fields remain identifiable.
- Source chunk coverage is visible.

For a complete project, also manually check that the last timestamp is close to the audio duration and that no chunk was omitted.

## Output recommendations

For human reading, produce Markdown with:

1. Processing note.
2. Verified Quranic text.
3. Complete timestamped transcript.
4. Editorial note describing normalization and uncertainty.
5. Quran verification sources.

For software, produce JSON containing raw text, normalized display text, timestamps, event types, Arabic text, confidence, notes, and source chunk IDs.

It is useful to package the Markdown and JSON together:

```bash
zip -j lecture_transcript.zip \
  working/transcription/lecture_latin_hausa.md \
  working/transcription/lecture_latin_hausa.json
```

## Troubleshooting

### The tool labels the recording as Arabic

Treat the language label as a hint, not a definitive classification. Inspect the actual text. Hausa explanation may be present even when the metadata says `ara`.

### Hausa appears in Arabic letters

Re-transcribe using enhanced audio if possible, then normalize contextually into Latin Hausa. Keep the Arabic-script output in `rawText` and flag low-confidence words.

### A chunk has no segments

Check duration and loudness. If it contains speech, retry only that chunk with 60-second subchunks. If it is genuinely silent, preserve a chunk record noting the silence.

### Credits are exhausted

Stop the transcription batch and report the credit error. Preserve successful outputs so the task can resume later without repeating paid requests.

### Quran wording is unclear

Do not guess. Keep the raw wording, label it uncertain, and verify against the audio and authoritative Quran text before publishing.
